## <span id="mental-model-one-intention-several-asynchronous-owners" aria-hidden="true" />From a manifest to a running Pod

You run `kubectl apply` and get a line saying a Pod was created. A second later the Pod still shows `Pending`. Both outputs can be correct. The first describes the API write; the second describes work the cluster has yet to finish.

A **Pod** is the unit that Kubernetes places on one node. The API stores its description first. The scheduler then finds a node that meets its requirements and records the assignment. A kubelet on that node observes the assignment and prepares it locally through the runtime. The node must set up the Pod's execution environment, obtain the image if needed, mount any required volumes, and start the containers. Status updates show what the cluster has observed so far.

Open **Inspect the Pod startup** to compare the evidence each step leaves behind. Look for the stored object, the assigned node, and the Ready condition as three separate observations.

## <span id="walkthrough-capture-evidence-at-each-boundary" aria-hidden="true" />Follow the evidence through the API and the node

The small Pod below goes in namespace `path-lab`. A namespace groups namespaced resources and scopes their names. Save this as `path-demo.yaml` in a disposable cluster. The manifest documents port 80. nginx starts the listener as part of its own behavior.

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: path-demo
  namespace: path-lab
  labels:
    app: path-demo
spec:
  containers:
    - name: web
      image: nginx:1.27.5
      ports:
        - containerPort: 80 # Documentation; nginx supplies the listener.
```

```bash
kubectl create namespace path-lab
kubectl apply -f path-demo.yaml
# Node and Pod IP appear only when the relevant work has completed.
kubectl -n path-lab get pod path-demo -o wide -w
# In another terminal, inspect conditions and event reasons.
kubectl -n path-lab describe pod path-demo
kubectl -n path-lab get pod path-demo -o yaml
```

Read the watch output in the order it appears. A Pod record can exist before its node name appears. A node name tells you the assignment happened. The Pod IP appears after network setup reports it. `describe` includes conditions, events, and container state. `get -o yaml` shows the same API object with several fields you did not supply, such as `status` and `metadata.uid`. Conditions are named observations, with reasons and messages that explain what a component reported.

## <span id="practice-compare-before-and-after-binding" aria-hidden="true" />Watch a Pod get assigned to a node

Try the next commands after the Pod has a node. `wait` checks its Ready condition. When the kubelet reports Ready, the cluster considers the Pod ready under its configured checks. `logs` reads output from the named web container; an idle nginx may produce little output before a request. `port-forward` then gives you a way to talk to this Pod from your machine. While it runs, open `http://127.0.0.1:8080/` in a separate terminal or browser and look for the nginx page.

```bash
kubectl -n path-lab wait --for=condition=Ready pod/path-demo --timeout=90s
kubectl -n path-lab logs path-demo -c web --tail=20
# Local access for this named Pod; not a Service or external load balancer.
kubectl -n path-lab port-forward pod/path-demo 8080:80
```

For contrast, inspect what you can see right after a new submit. A fast cluster can assign a node before your first watch result, so read events if the transition goes by too quickly. The [module lab](/labs/#m02) provides another chance to follow startup when a ReplicaSet replaces one of its Pods.

## <span id="pitfalls" aria-hidden="true" />Allow for work that continues after apply

`Pending` covers multiple stages. A Pod with no node and a `FailedScheduling` event needs help with placement. A Pod that has a node and a pull error needs help obtaining its image. A Pod can even be Running while its Ready condition is false. When an image is cached and the pull policy permits reuse, startup may have no visible registry download. Read the condition and its reason before inferring which step is slow.
