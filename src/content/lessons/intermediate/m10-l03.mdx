## <span id="mental-model-shutdown-is-a-coordinated-transition-with-a-deadline" aria-hidden="true" />What happens while a Pod shuts down

You need to reboot a worker hosting one of three API Pods. The other copies should keep answering traffic and active requests on the affected Pod should have time to finish. **Graceful termination** is the period between a deletion request and the forced end of a Pod’s running processes. The kubelet gives containers time to shut down. If a `preStop` hook is configured and runs, it spends part of that same budget before the runtime sends the stop signal.

Meanwhile, EndpointSlices mark the endpoint as terminating and normally unready for new traffic. Changes take time to reach forwarding components, and existing connections can stay open. The application can stop accepting new requests and finish existing ones during the grace period. Step through both sides of termination in the scene and see why changing endpoint readiness cannot finish a request the app is already handling.

## Watch the endpoint while the Pod exits

Use the [disposable kind lab cluster](/labs/#setup). This Pod’s `preStop` hook sleeps for 12 seconds so you have time to see the EndpointSlice change during its 25-second grace period.

```bash
kubectl --context kind-kv-lab get namespace kv-lab >/dev/null 2>&1 || \
  kubectl --context kind-kv-lab create namespace kv-lab
kubectl --context kind-kv-lab -n kv-lab apply -f - <<'YAML'
apiVersion: v1
kind: Pod
metadata:
  name: trace-shutdown
  labels:
    app: trace-shutdown
spec:
  terminationGracePeriodSeconds: 25
  containers:
    - name: web
      image: nginx:1.28.0-alpine
      lifecycle:
        preStop:
          exec:
            command: ["sleep", "12"]
---
apiVersion: v1
kind: Service
metadata:
  name: trace-shutdown
spec:
  selector:
    app: trace-shutdown
  ports:
    - port: 80
      targetPort: 80
YAML
kubectl --context kind-kv-lab -n kv-lab wait --for=condition=Ready \
  pod/trace-shutdown --timeout=90s
```

Start this watch and wait for `READY=true` and `TERMINATING=false`. Source `lab-env.sh` in both terminals so they use the same cluster.

```bash
kubectl --context kind-kv-lab -n kv-lab get endpointslices \
  -l kubernetes.io/service-name=trace-shutdown --watch \
  -o 'custom-columns=ADDRESS:.endpoints[*].addresses[*],READY:.endpoints[*].conditions.ready,TERMINATING:.endpoints[*].conditions.terminating'
```

Delete the Pod in the other terminal. Look for `READY=false` and `TERMINATING=true` while the Pod is still present. When it exits, its address disappears from the EndpointSlice. Stop the watch with `Ctrl+C`, then delete the Service.

```bash
kubectl --context kind-kv-lab -n kv-lab delete pod trace-shutdown --wait=false
kubectl --context kind-kv-lab -n kv-lab wait --for=delete \
  pod/trace-shutdown --timeout=60s
kubectl --context kind-kv-lab -n kv-lab delete service trace-shutdown
```

## <span id="walkthrough-allow-maintenance-without-removing-too-many-healthy-replicas" aria-hidden="true" />Keep enough replicas during maintenance

A **PodDisruptionBudget (PDB)** limits voluntary evictions performed through the Eviction API, such as those used by normal node drain. This example selects `app: api` in its own namespace and asks for two healthy copies to remain. If three matched Pods are healthy, the budget can allow one eviction. With only two healthy copies before the drain starts, evicting a healthy copy can be blocked until availability improves. Use the scene to try both cases.

```yaml
apiVersion: policy/v1
kind: PodDisruptionBudget
metadata:
  name: api-availability
spec:
  minAvailable: 2
  selector:
    matchLabels:
      app: api
```

## <span id="practice-read-the-budget-before-touching-the-node" aria-hidden="true" />Check the budget before draining the node

**Cordon** marks a node unschedulable for ordinary new Pods. Existing Pods remain. **Drain** requests eviction or deletion of eligible Pods and waits for them to terminate. A controller can create replacements, which need a suitable node and enough resources. In a disposable cluster, inspect the current and desired healthy counts and `ALLOWED DISRUPTIONS` before draining. Use a worker name from the cluster, and check application health before making it schedulable again.

```bash
kubectl get pdb api-availability
kubectl describe pdb api-availability
kubectl get pods -l app=api -o wide
# Only use a disposable worker obtained from kubectl get nodes.
kubectl cordon LAB_WORKER
kubectl drain LAB_WORKER --ignore-daemonsets
# After maintenance and health checks:
kubectl uncordon LAB_WORKER
```

Use the [workload controllers lab](/labs/#m10) to inspect a live disruption budget before trying a drain. To practice rescheduling a replica during maintenance, use a disposable cluster with a spare eligible worker.

## <span id="pitfalls-a-force-action-changes-the-safety-boundary" aria-hidden="true" />Recognize disruptions the budget cannot prevent

A PDB cannot prevent a node crash. Direct Pod deletion can bypass the Eviction API, and a Deployment’s rollout follows its own update settings. If a drain is blocked, inspect unready Pods, the budget, and placement capacity before changing the procedure. Draining with `--ignore-daemonsets` leaves DaemonSet-managed Pods for the node’s system workload requirements.
