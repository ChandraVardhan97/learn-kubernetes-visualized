# Advanced curriculum technical audit

Reviewed 2026-10-27 against live primary documentation. Scope: every MDX lesson and JSON scene in `src/content/lessons/advanced` and `src/content/scenes/advanced`, plus read-only comparison with every file under `public/labs/m14` through `public/labs/m20`. Shared duplicate lab helpers were compared once by content hash. No cluster commands, lab mutations, publishing, commits, or new tests were performed by this audit.

This is a documented technical review, not a guarantee that every possible platform, configuration or future release behaves identically. The root audit separately verifies published release baselines and runtime results. Existing Kubernetes 1.37 metadata and image pins were retained; the etcd references below were aligned with the published 3.7 documentation. Moving `master`, `stable`, and `latest` documentation references were read on the review date and may change later.

## Corrections made

1. **m14-l01:** made admission dry-run side-effect declarations explicit and distinguished webhook call failures from an explicit denial. `failurePolicy: Ignore` does not bypass `allowed: false`. The policy/binding example remains a separately scoped optional exercise.
2. **m14-l02 and its JSON:** replaced the outdated blanket prohibition on version ordering with the current API contract. Same-resource ordering does not permit treating a version difference as a count of events or elapsed time. Preserved reconnect, expired-history relist, and unchanged-cursor handling. Also replaced waiting on metadata.generation alone with documented status/observed-generation evidence.
3. **m14-l03:** distinguished GA API lifetime protections from beta/alpha removals and from a platform author's CRD policy. Updated the redirected deprecation-policy URL to its canonical destination.
4. **m16-l01:** explained that a nested required list does not make its parent field mandatory. The associated schema gap is recorded below for the lab owner.
5. **m16-l02 and its JSON:** clarified that sampled child readyReplicas can belong to an earlier Deployment generation. The teaching controller's processed parent generation and ready count do not establish current-revision readiness.
6. **m17-l01:** changed the optional memory demonstration to run `dd` directly. A shell that runs `dd; sleep` could survive a killed child and obscure the container termination being investigated. The mandatory lab already runs `dd` directly. Runtime/kernel caveats remain explicit.
7. **m18-l01/m18-l03:** changed etcd source references from 3.6 to 3.7, and removed obsolete opaque-version wording from the restore discussion. Recovery still treats etcd revision bumping as a server recovery operation.
8. **m19-l03:** made the NetworkPolicy example an additive allow rule under ingress isolation, including the documented node-traffic exception, instead of implying a universal exclusive firewall.
9. **m20-l02:** aligned backup/restore prose with the actual private output directory and `kubectl cp` restoration. The lab verifies the captured fixture before deletion and checks exact bytes/checksums before and after Pod replacement; it no longer uses the previously described raw stdin restore.
10. **m19-l01:** required selecting a supported Argo CD release and checking its tested Kubernetes matrix before the optional installation. Pinning a manifest is not compatibility evidence.

## Lab findings referred to the root audit

No lab file or `src/data/labs.ts` was edited by this reviewer.

- **Required correction:** `public/labs/m16/crd.yaml` and its m20 copy define required child fields under `spec` but do not require the parent `spec` field. Add `required: [spec]` immediately under the root `openAPIV3Schema.type: object`, alongside its `properties`. Otherwise a spec-less WebApp can be accepted and make the minimal operator exit when indexing `obj['spec']`. After referral, a read-only final check confirmed that the root audit added the root-required field in both copies. No admission/runtime test is claimed by this reviewer.
- **Documentation precision:** m15 README says the script displays the kube-controller-manager leader Lease specifically; the script actually lists all kube-system Leases. After referral, a read-only final check confirmed that the root audit changed it to “lists the control-plane leader Leases in kube-system.”
- **Required optional-recipe correction:** m19 `ARGOCD-OPTIONAL.md` pins Argo CD 3.2.3. Its [release-3.2 tested matrix](https://argo-cd.readthedocs.io/en/release-3.2/operator-manual/tested-kubernetes-versions/) lists Kubernetes 1.31–1.34. The [current stable matrix](https://raw.githubusercontent.com/argoproj/argo-cd/stable/docs/operator-manual/tested-kubernetes-versions.md) lists Argo CD 3.3–3.5 and no Kubernetes 1.37 coverage. The [release policy](https://argo-cd.readthedocs.io/en/stable/developer-guide/release-process-and-cadence/) limits fixes to the latest three minor versions; 3.2 is therefore EOL at review time. Replace this runnable old recipe with a research-only extension requiring a supported pinned release, a matching upstream-tested Kubernetes target and separate runtime validation. Simply changing its pin to the current [stable VERSION](https://raw.githubusercontent.com/argoproj/argo-cd/stable/VERSION) (3.5.6 when read) would not establish Kubernetes 1.37 compatibility.
- **Retained implementation limitation:** the operator checks ownership before applying, using separate API requests. This is useful for the single-process exercise but is not an atomic adoption lock against concurrent replacement by another actor. Keep its production limitations explicit; no claim of race-proof adoption or fencing was added.
- **Retained implementation limitation:** minimal status is sampled immediately after child apply. It is intentionally not a production Ready condition; no status or leadership redesign is required to teach this bounded mechanism.
